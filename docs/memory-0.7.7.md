# 0.7.7 描画キャッシュの所有参照

BatteryAdapterのWeakHashMapはDrawableをキーとしていたが、値のStateが同じDrawableを未使用のフィールドに強参照していた。この逆参照を除去し、キャッシュだけを理由に古いDrawableを保持しないようにした。色の復元・Paintのコピー・描画の判定・フェードのコードは変更していない。

## 検証

既存JVMテスト209件、releaseビルド、lintが成功。Android 16/17のCOWエミュレーターで、SamsungのPaintフィールド契約を持つ小さなテスト用Drawableを作り、本物のStateを構築した。キャッシュ自体を保持したままDrawableの弱参照とWeakHashMapエントリーが回収されることを確認した。

所有者が生存中には、文字用のPaintが元のPaintを変えず指定した白のコピーへ変換されることも確認した。SystemUIへのフック・カメラ操作・画面録画・専用テストActivityは使っていない。GC要求は仮想端末のテスト専用で、製品や実機へ定期GCは追加していない。

実機でこの旧Drawableが何個溜まっていたか、何MB減るかは未測定。更新後に既存SystemUIへ反映するには対象だけの再読み込みが必要。端末全体の再起動は不要。
