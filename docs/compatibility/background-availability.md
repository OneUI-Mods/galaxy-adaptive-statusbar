# 背景が未確定なフレームの扱い

## 0.6.19-experimental

報告された状態は `Capture OK` の後も `Last error: Undefined/transparent background` が残るものだった。Last errorは過去の例外を保持するので、その表示だけで現在停止中とは判断しない。

従来はサンプル対象のalphaが250未満なら通常のIllegalStateExceptionを投げ、メインスレッドのfail経路でepochを進め、配色を復元し、連続エラーを加算していた。履歴やウィンドウ切り替え時の一時的な透明フレームが5回続くと、同じ経路で自動処理が停止する。

画素からのサンプル抽出をBackgroundSamplesへ分離。透明・空領域は専用のUnavailableとして扱い、標準色へ戻して次のフレームを待つ。真の不正バッファ・不正な領域は通常の例外として扱う。保護された背景の専用処理は維持し、保護画面を読み取る変更はしない。Surfaceが存在しない一時待ちも連続エラーを0に戻す。背景が未確定でも毎回ミラーを作り直さない。

全ターゲットの分析が成功した後だけ、次フレーム向けの前回色を更新する。一部のターゲットだけを分析できたフレームはヒステリシスの履歴へ混ぜない。

画素の透過、対象外の透過画素、空領域、正常フレームへの復帰、不正バッファ、従来のalpha閾値をJVM試験で確認。全123試験、release Lint、releaseビルド成功。署名済みrelease APKの上書きインストールは成功した。その後TailADBのTCP接続がタイムアウトし、別ADB serverでも再接続できなかった。利用者の指示によりSystemUIの再読み込み・実機確認は後日へ延期している。

GitHub ActionsもJVM試験・Lint・各ビルド・release APK構造検査は成功したが、開発用artifactのアップロードが保存容量上限で失敗した。これはコード検証の失敗とは分けて記録する。その後、利用者の明示指示により、この会話のアプリ7本を公開リポジトリに揃え、Actionsの開発用artifactを削除する。Releaseの署名済み配布物は維持する。
