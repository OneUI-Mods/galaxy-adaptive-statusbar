# One UIホーム追従の開発状況

0.5.0を開発中です。最初の試作では開く動作の受け渡しが遅く、履歴カードの経路も不足していました。iPhoneミラーリングで実機の開く・閉じる・履歴への縮小・履歴からの復帰を観察し、文字ごとの自動配色と両立するライブ描画へ変更中です。GitHub Releaseは更新していません。

## 対応する経路

- One UIホーム17.5.03.27 / Android 16 / 指定のOne UI 8.5ビルドに限定。
- One UIホームの`PlayerImpl.makeUpdateInfo`から、通常・Home Upの計算後の実際の位置、crop、拡大率、透明度、角丸を取得。通常のValueAnimPlayerとHome UpのSpringAnimPlayerを共通の出力で扱います。
- 開始・終了・中断は同じPlayerとAnimatorSetから取得。実際に選ばれたcalculatorの位置アニメーション時間とAndroidのduration scaleを参照し、最後の250msまたは幅80%の早い方で受け渡します。急速なease-outでほぼ全画面になるまで待つ問題を避けます。ばね・ジェスチャーの残り時間を直線速度から外挿せず、実際の幅で受け渡しを判断します。
- `catch`/`moving`を観測し、AnimatorSetが停止中のジェスチャーも取得。同じタスクの連続した座標なら、アニメーターや開閉方向が変わっても記録画像とフェードを引き継ぎます。幅に応じてホーム側へ戻せる可逆の透明度と変化速度の上限を使い、反転でフェードを再初期化しません。
- 終了通知は48msだけ受け渡しを待ち、直後の置換アニメーターへ接続。古いフレームや終了通知が新しい動作を終了させないようにします。指を止めている間は75msごとの同じ座標の生存通知だけを送信し、消灯・ロック・OFFでは停止。画像の再取得は行いません。
- SystemUIは自分の文字・アイコン等のViewと元の配置を保持し、タッチを受け取らない専用WindowContextの透明ウィンドウへライブ描画。固定画像は使いません。元の親Viewの非表示やalphaを引き継がず、文字の色Span・アイコンtint・電池の部位別描画は現在値を使います。他アプリの画像はコピーしません。
- 追従中も背景色判定と色フェードを継続し、文字ごとの判定領域を現在のウィンドウ座標へ変換。元のバーと追従ウィンドウの両Surfaceをキャプチャから除外します。移動中の結果と通常表示の結果は世代で分離し、消灯・ロック・OFF時にはキャプチャを停止します。
- 履歴への進入はRecentsAnimationManager、表示中はTaskSceneViewの実際のカード配置・拡大率・角丸を取得。動いている間は描画前の配置を観測し、静止中は75msの生存通知を使います。カードからの復帰は別経路のTaskLaunchTransitionのmatrixとcropを読み取ります。現段階では現在のタスク1枚・単一ウィンドウ・縦画面が対象で、別カードや分割画面の複製は行いません。
- 接続先の登録はSystemUI、取得とフレーム送信はOne UIホームのUIDに限定。転送するのは座標のみです。古いフレーム、不正な値、別セッションの遅延結果を拒否します。
- OFF、消灯、ロック、回転、中断、220msの更新途絶で元のバーを復元します。
- SystemUIとOne UIホームで個別の永続クラッシュ履歴を持ち、それぞれ2分以内の3回の異常終了で次回起動からフックを停止。ホーム側は実際にフックを入れる直前に履歴を記録し、無効中の起動は記録しません。フック初期化・コールバックの例外は即時に自分のフックを解除して保護をラッチし、ON/OFFや再起動では再試行しません。UIからの明示的な解除では両プロセスを再読み込みし、自動配色はOFFのままにします。

AOSPも[ランチャーのアプリ遷移とステータスバー表示のタイミングを連携](https://android.googlesource.com/platform/packages/apps/Launcher3/+/refs/tags/android-14.0.0_r11/quickstep/src/com/android/launcher3/QuickstepTransitionManager.java)しています。本実装の対象は上記Samsung製ランチャーの実機バージョンです。

## 現在までの確認

- 単体テスト52件成功。従来の45件に加え、早いease-out、閉じ始めの即時追従、履歴の減光と復帰、移動後の文字ごとの座標と配色・反転・overshootを検証します。
- releaseビルド、署名、zipalign、検証用Activityの除外、Lintに成功。
- 署名済みの実機テストAPKでIPC権限とParcelの検査2件に成功。
- 実機の既存OFF/ON試験1件に成功。ロック中に取得数が増えず、停止状態と再有効化を確認。
- 反転対応後のrelease版でもIPC試験2件、ロック中のOFF/ON試験1件に成功。両プロセスの保護UI試験2件にも成功し、画面の初期表示・プログラムからのスイッチ変更でもONに戻せないことを確認。
- ホームの保護履歴へ3件の直近異常終了を与える非破壊の実機試験に成功。次の起動とさらにその次の起動で保護が維持され、どちらにも追従フックが入らず、自動配色がOFFになることをログ・永続状態・設定で確認。実際のクラッシュは発生させていません。試験後は元の設定・正常な保護履歴を復元して比較確認。
- Vectorの対象へOne UIホームを追加。両プロセスでフックとEngineの初期化に成功。クラッシュ保護の検出回数は0。
- Home Upの設定2ファイルを退避し、全設定が変わっていないことを比較確認。自動消灯設定も元の値へ復元。

## 検証中に修正した問題

- ロック中など設定画面の`onResume`が呼ばれない状態では、従来の定期更新前にONスイッチが有効に見える問題を検出。初期表示とスイッチ変更時にも保護を確認するようにし、両プロセスのUI試験を再実行して成功。
- ADB接続先の確認コマンドが本来のコマンド向けの標準入力を消費し、試験用データが空になる問題を検出。保護が`guard_error`で安全側に停止したことを確認し、退避ファイルをバイト単位で検証して復元。接続先の探索では標準入力を閉じる修正を行い、実機への標準入力の往復と既存Python試験4件を確認。履歴による停止試験は転送の照合を追加して再実行し成功。

## 解除後の必須確認

1. 現在のHome Up設定で、ホームのアイコンから実際に開閉して画面収録する。移動中のバー、固定側の消え方、最後の復帰、二重表示・ちらつき・位置ずれをフレームで確認する。
2. One UI側の子RenderNodeのalphaやtintがコピー側へ与える影響を確認する。必要なら独立したhardware bitmapへ固定する。
3. Home Upの開く動作とジェスチャー動作の調整を一時的にOFFにし、通常設定でも同じ試験を行う。調整値を初期化せず、元の設定へ戻して比較する。
4. 途中反転・連続開閉・設定OFF・消灯を試し、元のバーが必ず戻り、透明ウィンドウが残らないことを確認する。
5. 新しい設定Switch、5言語、既存の色フェード・保護UIの回帰を確認する。

確認後にREADME・CHANGELOG・利用者向けのリリース文を仕上げ、署名済みrelease APKを改めてパッケージ化します。既存タグを移動せず、新しいタグで配布します。
