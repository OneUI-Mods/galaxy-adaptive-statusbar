# One UIホーム追従の開発状況

0.5.0を[実験版として公開](https://github.com/ryuya0124/galaxy-adaptive-statusbar/releases/tag/v0.5.0-experimental)しました。最初の試作では開く動作の受け渡しが遅く、履歴カードの経路も不足していました。iPhoneミラーリングで実機の開く・閉じる・履歴への縮小・履歴からの復帰を観察し、文字ごとの自動配色と両立するライブ描画へ変更しました。以下は実装と検証範囲の記録です。

## 対応する経路

- One UIホーム17.5.03.27 / Android 16 / 指定のOne UI 8.5ビルドに限定。
- One UIホームの`PlayerImpl.makeUpdateInfo`から、通常・Home Upの計算後の実際の位置、crop、拡大率、透明度、角丸を取得。通常のValueAnimPlayerとHome UpのSpringAnimPlayerを共通の出力で扱います。
- 開始・終了・中断は同じPlayerとAnimatorSetから取得。実際に選ばれたcalculatorの位置アニメーション時間とAndroidのduration scaleを参照し、最後の250msまたは幅80%の早い方で受け渡します。急速なease-outでほぼ全画面になるまで待つ問題を避けます。ばね・ジェスチャーの残り時間を直線速度から外挿せず、実際の幅で受け渡しを判断します。
- `catch`/`moving`を観測し、AnimatorSetが停止中のジェスチャーも取得。同じタスクの連続した座標なら、アニメーターや開閉方向が変わってもライブ描画の対象とフェードを引き継ぎます。表示中の透明度から別の目標へつなぎ、反転でフェードを再初期化しません。
- 終了通知は48msだけ受け渡しを待ち、直後の置換アニメーターへ接続。古いフレームや終了通知が新しい動作を終了させないようにします。指を止めている間は75msごとの同じ座標の生存通知だけを送信し、消灯・ロック・OFFでは停止。停止中の位置を推測して動かしません。
- SystemUIは自分の文字・アイコン等のViewと元の配置を保持し、タッチを受け取らない専用WindowContextの透明ウィンドウへライブ描画。固定画像は使いません。元の親Viewの非表示やalphaを引き継がず、文字の色Span・アイコンtint・電池の部位別描画は現在値を使います。他アプリの画像はコピーしません。
- 追従中も背景色判定と色フェードを継続し、文字ごとの判定領域を現在のウィンドウ座標へ変換。元のバーと追従ウィンドウの両Surfaceをキャプチャから除外します。移動中の結果と通常表示の結果は世代で分離し、消灯・ロック・OFF時にはキャプチャを停止します。
- 履歴への進入はRecentsAnimationManager、表示中はTaskSceneViewの実際のカード配置・拡大率・角丸を取得。動いている間は描画前の配置を観測し、静止中は75msの生存通知を使います。カードからの復帰は別経路のTaskLaunchTransitionのmatrixとcropを読み取ります。現段階では現在のタスク1枚・単一ウィンドウ・縦画面が対象で、別カードや分割画面の複製は行いません。
- 接続先の登録はSystemUI、取得とフレーム送信はOne UIホームのUIDに限定。転送するのは座標のみです。古いフレーム、不正な値、別セッションの遅延結果を拒否します。
- OFF、消灯、ロック、回転、中断、220msの更新途絶で元のバーを復元します。
- SystemUIとOne UIホームで個別の永続クラッシュ履歴を持ち、それぞれ2分以内の3回の異常終了で次回起動からフックを停止。ホーム側は実際にフックを入れる直前に履歴を記録し、無効中の起動は記録しません。フック初期化・コールバックの例外は即時に自分のフックを解除して保護をラッチし、ON/OFFや再起動では再試行しません。UIからの明示的な解除では両プロセスを再読み込みし、自動配色はOFFのままにします。

AOSPも[ランチャーのアプリ遷移とステータスバー表示のタイミングを連携](https://android.googlesource.com/platform/packages/apps/Launcher3/+/refs/tags/android-14.0.0_r11/quickstep/src/com/android/launcher3/QuickstepTransitionManager.java)しています。本実装の対象は上記Samsung製ランチャーの実機バージョンです。

## build 14でのフェード調整

- iPhoneミラーリングで時計の起動・履歴への縮小・履歴からの復帰を再観察。起動では固定側が薄く残る間に別位置のアプリ側が現れ、復帰ではカード上の薄い時計が拡大中に明るくなることを確認。ミラーリングのフレームと入力遅延があるため、Apple側の正確な時間・曲線の測定値とはしていません。
- 透明度の合計を常に1とする85msの線形追従から、独立した非線形フェードへ変更。固定側は90msのease-out、動く側は35ms遅らせて140msのsmoothstepを使います。閉じる際は動くバーを先に消し、ホーム側を後から出します。これらの値は実装上の調整値です。
- Choreographerで透明度を画面の各フレームへ反映。ホームからの更新が静止・75msの生存通知になっても階段状にならず、完了後の追加コールバックは停止。終了時も未完了のフェードを途中で切り上げず、OFF・消灯・異常時は即時解除します。Androidのduration scaleを反映。
- 指を止めている間はカード側を保持し、ホームへ戻すことが確定した動作でホーム側へ受け渡す。履歴カードが後から接続した際は、最初から減光した状態で表示。履歴からの復帰は終盤の実際の幅で明るさを戻します。
- Safariへ通信しないdata URLの比較ページを入力し、背景とtheme-colorの白黒切替を観察。背景と文字が同時に新しい白黒となるフレームを確認し、約50〜90ms間隔の観測では長い灰色の途中状態を捉えていません。他アプリやiOS全体の更新方式・内部描画方式を断定する根拠にはしていません。混在背景での追加観察は下記。
- 開く直前から縮小中のアプリを判定してホーム側を先に変色させる問題を修正。離れる側が十分に消えるまで既存色を保持し、動く側と戻ったホーム側で背景判定の座標を切り替える。画面が替わる最初の配色は前画面の色から補間せず、以後の文字ごとの更新では利用者の色フェード設定を維持します。状態変更で古い解析・フェードを破棄。
- 混在背景の観察用HTMLは`tools/ios_contrast_reference.html`。ブラウザが実際にステータスバー領域へどの背景を表示しているかも確認し、単色へ置換される場合は部位別判定の証拠として扱いません。

### iPhoneの混在背景での追加観察

- Safariで左右白黒分割・反転、24 CSS pxの細い縞と移動、140 CSS pxの太い縞の移動を確認。ページ先頭では上部が白い領域になるため、スクロールして実際の混在背景がステータスバー直下へ来た状態を比較しました。上端にはSafari側のぼかしが見え、本文の明暗境界をそのまま判定入力と見なすことはできません。
- 左白・右黒で時計は黒、右側は白。左右を反転すると時計は白、右側は黒。同じバー内で白黒が共存することを確認。
- 細い縞では移動しても観測した文字・アイコンは黒を維持。太い縞は6秒周期で1周期を約50〜90msごとに比較し、時計と右側が別々に切り替わることを確認。右側でも電波・Wi-Fi・電池が常に一括で同色とは限りません。
- 時計の下を太い境界が横切る間、時計は同じ色を保ち、途中に灰色のフレームを挟んで全体が切り替わりました。このSafariの条件では時計1文字ごとの反転は確認できません。正確なフェード時間、ヒステリシス、内部の判定範囲や描画手法は断定しません。
- Galaxyの文字別配色を廃止する根拠にはせず、細かい配色の維持と、画面遷移時の色・透明度の受け渡しを別の課題として扱います。比較用に作成したSafariとChromeのタブだけを閉じ、既存の閲覧タブや設定は変更していません。

## build 17での保護画面後の不揃い表示対策

- 利用者の途中停止画像ではカード内にGalaxyの追加表示と電池残量だけが見え、同時期に配色がSecure layersの連続失敗で停止していたことを確認。通常の配色へ復帰させると、同じ深さの保持ジェスチャーで時計・アイコン・追加表示が揃って追従しました。
- SystemUIの追加表示は同じステータスバー内にあり、別ウィンドウの残留は確認できませんでした。機能OFFでも同じ保持・反転操作を行い、通常のバー全体が固定位置となり、カード内に追加表示だけが焼き込まれている状態ではないことを比較確認。
- 保護されたフレームの拒否を専用のSecurityException派生型にし、画素へアクセスせずバッファを解放。配色と追従を一緒に一時停止し、成功した新しい背景取得で自動復帰します。拒否中は最大5Hz、消灯・ロック中は取得しません。
- 保護されたフレームの拒否を通常の連続エラーへ加算しません。その他の取得エラーの5回停止では位置追従も停止し、設定の定期読出しで追従だけ復活させないよう変更。初期化・コールバック失敗と永続クラッシュ保護の解除条件は変更しません。
- 失敗や一時停止中にも動作状態を報告するよう変更。保護画面を表示したまま待機しても連続エラー停止にならず、保護を外すとON/OFFなしで配色と追従を再開する実機試験に成功。
- 実機9件（保護停止と自動復帰、保持・反転中のライブ配色、キャプチャ3件、履歴とOFF時の削除、フェード途中OFF/連続切替2件、標準色更新のちらつき1件）、単体64件、Lint成功。追加で機能OFFの標準動作比較も成功。試験用APKと私的な画像は配布APKへ含めません。

## 検証中に修正した問題

- ロック中など設定画面の`onResume`が呼ばれない状態では、従来の定期更新前にONスイッチが有効に見える問題を検出。初期表示とスイッチ変更時にも保護を確認するようにし、両プロセスのUI試験を再実行して成功。
- ADB接続先の確認コマンドが本来のコマンド向けの標準入力を消費し、試験用データが空になる問題を検出。保護が`guard_error`で安全側に停止したことを確認し、退避ファイルをバイト単位で検証して復元。接続先の探索では標準入力を閉じる修正を行い、実機への標準入力の往復と既存Python試験4件を確認。履歴による停止試験は転送の照合を追加して再実行し成功。

- 履歴へ切り替える実機操作で、キャプチャ結果のHardwareBufferがnullでも後処理がcloseを呼び、連続エラー停止になる問題を検出。結果・バッファ・Bitmapが欠けるフレームを一時的な取得不可として扱い、存在するリソースのみ確実に解放するよう修正。空の結果から次の有効フレームへ復帰、Bitmap欠落時の解放、保護コンテンツ拒否を実機回帰試験へ追加。

- 上記の実機回帰試験3件に成功。続いて履歴操作で縮小キャプチャのサイズ検証が停止条件になる問題を検出。独立mirrorプローブで1201×117のcropが600×58へ切り捨てられることを実測し、四捨五入の検証を切り捨てへ修正。奇数サイズ・非ゼロ原点の回復試験を追加。
- 追従ウィンドウがタッチを妨げるというOne UIのトーストを検出。実機と同版のInputManagerService.notifyUntrustedTouchからの通知であることを確認。標準SystemUIの充電エフェクトと同じtrusted overlay設定と、入力チャンネルなしの設定を追加。他アプリやシステム全体のタッチ保護設定は変更しません。
