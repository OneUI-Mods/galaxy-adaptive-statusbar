# クラッシュ保護の誤作動調査（未配布の修正）

## 端末から確認できたこと

対象はGalaxy Adaptive Bar。読み取り時点ではSystemUI・One UIホームともblocked=false、確認済み異常終了のカウント0だった。解除トークンは前回取得時から変わっており、停止中の原因フィールドは解除により更新されていた。

直近のuser 0の終了履歴では、SystemUIはSIGTERM（signal 15）、One UIホームはSIGTERMとUSER_REQUESTED / FORCE STOPが中心だった。今回の停止時点に対応する状態ファイルやmodernログは残っておらず、今回の発動原因そのものは断定できない。古いLegacy Bridgeのログを今回の発動の証拠にはしていない。取得した状態・終了履歴はGit管理外のevidence/device/guard-audit-2026-10-17へ保存した。

## 再現・修正した経路

1. 旧実装は終了履歴が未取得・UNKNOWNのまま30秒以内に3回の監視対象プロセス起動が残ると、unknown_rapid_restartsで停止していた。終了理由の欠落だけでは異常終了の証拠にならない。終了履歴が届かない正常な再読み込みを模擬した回帰テストは修正前に失敗し、修正後に成功した。不明な終了だけで停止する分岐を削除し、後から確認できた異常終了は従来どおり数える。既知のSIGTERM・SIGKILL・低メモリ・更新・強制停止の除外は維持する。
2. SystemUIでは設定OFFでも起動時から監視対象になっており、OFFにしてフックを除去した後もPIDが残っていた。監視開始を配色フックの有効化直前に移し、無効化が完了したPIDは監視から外す。ホーム側も追従フックの無効化完了時に監視を外す。有効化し直した場合は新しい時刻で監視を再開する。
3. 停止理由と時刻を状態ファイルのlast_stop_cause / last_stop_atに保存し、解除で消さない。新フィールドを持たない既存ファイルも読み込める。既にラッチされた停止はアップデートだけでは解除しない。

確認済みの異常終了が2分以内に3回なら停止する判定、フック処理の例外での即停止、明示的な解除まで再試行しない動作は維持した。
