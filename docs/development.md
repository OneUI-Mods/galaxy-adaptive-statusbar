## ソースとビルド

Android SDKのコンパイル対象は37です。JDK・Gradle・依存関係の版は、リポジトリ内のGradle設定とwrapperを基準にしてください。

```sh
./gradlew :app:assembleRelease
```

配布にはrelease variantを使い、配布鍵による署名とAPKの構造を検証します。debug APKやテスト専用画面を含むAPKを配布しません。署名鍵・パスワード・端末ログ・外部アプリのバイナリをGitへ追加しないでください。

## 通知のオーバーフロードット

`StatusBarIconView`の通知アイコンはImageViewのフィルターで描画色を変更できますが、オーバーフロードットは`onDraw(Canvas)`内で独立した`mDotPaint`を使います。Android 16・17の保存済みSystemUI APKで、`setDecorColor(int)`が`mDecorColor`を保存し、`updateDecorColor()`がドットのPaintを更新する経路をそれぞれ確認しています。

`NotificationIconTintAdapter`はこの設定メソッドを利用し、ImageViewの配色と同じフェード値を渡します。純正の表示状態・半径・出現アニメーション・Doze補間は変更しません。通知設定のOFF、画面の消灯、対象の消失、エンジン停止時に最新の純正色へ戻します。配色中の純正テーマ更新も記録し、次のキャプチャまで純正色が一瞬見えることを防ぎます。純正の色に含まれる透明度は保持します。

対象クラスとメソッド・フィールドは独立したAndroid 16・17のDexKitプロファイルに追加しています。起動時の型・署名確認が失敗した場合はこの追加アダプターのみ停止します。JVMの回帰試験ではテーマ変更中の色保持、OFF時の最新色の復元、連続フェードで透明度が累積しないことを確認します。実機の描画確認はビルド試験とは別に記録します。

## 配色単位（0.7.2）

`color_grouping` は `characters`（既定）と `parts` を保存します。未設定・未知の値は従来の文字ごととして扱います。ContentProvider経由で両OSの共通Engineへ渡し、変更時はターゲット世代・分析世代を進めて旧キャプチャとフェード・文字spanを破棄します。設定の定期再取得でもモード差分を検出します。

`TextColorUnits` は文字モードでは既存と同じBreakIteratorのUTF-16範囲を使います。パーツモードでは時計が日付と時刻を同じTextViewへ入れる場合も分割し、秒・ロケールの午前午後を時刻に含めます。日付専用Viewは時計の設定に含めます。認識できない書式や複数の時刻がある表示は、表示全体を1パーツとして維持します。アイコン・通信速度・電池の既存アダプターと内部残量文字のコントラスト処理は継続します。

`TextUnitBounds` は各範囲の選択パスから左右の範囲を取得し、フォントの描画範囲と合わせます。RTLの文字列や改行を含むパーツにも対応し、通常時とアプリ開閉への追従中で同じターゲットを使います。

JVM 180件（新規の範囲分割・既定値・ロケールなど12件を含む）、Python 4件、release Lintを通過しています。専用のAndroid 17 / API 37 ARM64エミュレータでは、左右の部品境界・改行をまたぐ部品・RTLの描画範囲・設定保存とProviderの即時反映の4件を通過しました。実機を操作せず、Samsung純正表示での最終確認は未実施です。

## 自動配色単位（0.7.3）

`auto` は日付・時刻のパーツごとに独立して判定します。UIスレッドでパーツと書記素の両方の座標を取得し、キャプチャworkerが同じフレームの背景で比較します。空白領域や大きい字幅への偏りを抑えるため、各書記素から等数のサンプルを集めます。実際に選ばれる単色／文字色のコントラスト比を比較するため、画像の分散が大きいだけでは文字単位へ変えません。

20パーセンタイルと中央値の対数平均を読みやすさの指標にし、共通色でコントラスト3未満の字が改善し、全体の改善率が1.12以上になると文字単位の候補にします。これらは自動モード用の判定指標であり、すべての画像で可読性を保証する数値ではありません。判定方法と反転抑制は既存の設定を引き継ぎます。

通常の切り替えは100msの継続を要求し、明らかな低コントラストではすぐ文字単位へ移ります。パーツへ戻す場合は650msの安定を待ちます。粒度が変わるときは同じViewの重なる既存文字の色からフェードを開始します。設定・パレット世代の変更で判定履歴を破棄し、不要なパーツの履歴は各フレームで削除します。アプリの開閉中には文字とパーツの両方の矩形を同じ変換で写します。

単体試験では均一な白黒・中間色、明るい建物と暗い道路を模した背景、同じ複雑さのテクスチャ、孤立ノイズ、判定の継続時間とパーツ間の独立性を確認します。

### 実機での確認（2026-11-04）

Android 17 / One UI 9のSM-S948Qへ署名済みreleaseを上書きし、Galaxy ReloadからSystemUIだけを再読み込みしました。解除状態を維持し、OS・system_server・One UIホームは再起動していません。通常の文字モードは10span、パーツモードは日付と時刻の2spanとして描画されました。

自動モードは白／黒背景で2span、白黒の縞で10spanへ切り替わりました。Googleマップの航空写真を東京・日本橋付近でパンし、7サンプルで2、10、6、6、6、2、2spanを確認しました。6spanは一方のパーツのみが文字単位になった状態です。これらは画像全体を一律に分類せず、日付・時刻で独立して読みやすさを判定することの実機確認です。すべての写真・縮尺・端末を検証したものではありません。

パーツへ戻す待ち時間では、各文字を先に共通色へフェードさせます。650ms待ってからspanをまとめるため、最大500msのフェード設定でも統合時の色飛びを防ぎます。この時系列を追加のJVM試験で確認しています。


## キャプチャ負荷の抑制（0.7.4）

`CapturePacing`はメインスレッドの要求判定とキャプチャワーカーの完了通知で共有する。判定時に描画のレイアウト探索を先送りし、追加の取得タスクを積まない。色の粒度・パレット・アプリ開閉の変更でも、負荷制限を迂回しない。OFF・消灯・ロックはこの待機を通さず既存の復元／ミラー解放へ進む。

測定範囲は`captureLayers`とCPU読み戻しで、初回のミラー準備待機50msは含めない。120fpsの8.33msを基準に、超過時は最低250ms、2周期以上で1000ms、4周期以上で2000ms、12周期以上で5000msの休止を取得完了後に入れる。ユーザー設定の上限も尊重する。高速な通常取得は開始間隔を維持し、遅れた分の連続取得を行わない。

頻度を戻すには6回連続の安価な成功を必要とし、その6回で最も重かった区分へ戻す。失敗は回復として数えず、短い失敗も最低250ms空ける。`Capture rest`を状態表示へ追加した。閾値は表示FPSの保証ではなく、合成側の高コスト処理を繰り返さないための保護。

Android 16/17のキャプチャAPIと既存フックは変更しない。SurfaceFlingerの残留描画状態の発生元や、残留状態自体を解消する修正ではない。重い経路の要求頻度を減らす暫定的な対策であり、高負荷時には背景色への追従が遅れる。


### 検証記録（2026-11-08）

新規8件を含むJVM 201件、ホスト4件、releaseビルド・Lintを通過。設定上限、重い処理の完了後休止、連続即時要求による迂回防止、6回の回復条件、回復中の最も遅い区分、失敗・不正値の扱いを確認した。画面操作禁止のため、この時点では実機フック再読み込み・実FPSの改善確認は未実施。既存SurfaceFlinger状態は調査時のまま維持する。
