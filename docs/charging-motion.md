# 充電中のステータスバー表示（Android 17）

SM-S948Q / BZI9のSystemUIと同一ハッシュの実機APKを解析した。Samsungの充電VIはCompose側の充電Flowを使い、HomeStatusBarViewModelの別の5入力combineがバー全体を隠す。充電Flowそのものは変更せず、後者のinvokeの第5入力（充電による非表示理由）だけを無効化する。ロック・アプリ全画面・Samsungイベント・disable flagsの判断は純正に残す。

SamsungBatteryStatusChipのgetSystemIconAnimatorは、元のBatteryMeterViewのalphaとstatusIconsの固定距離移動を別々に作る。元電池のalphaは保持する。固定距離移動のupdateだけを、対象Viewの同一性を確認したSession中に置換する。充電チップbackgroundの実変換行列と画面上の境界から、各描画前に必要な左移動を算出する。移動先は純正springのオーバーシュート・方向反転・縮小に追従する。アイコン座標を直接代入せず、Choreographer同期の臨界減衰springで位置・速度を連続に更新する。純正resetの後も現在位置を保持し、最後の右移動が収束してから解放する。消灯・無効化・ステータスバーdetachなどの中断は直ちに復元する。

隣接ViewのtranslationXだけを所有し、他のparent移動は画面座標へ含める。純正の電池アンカーを動かさない。初期フレームで隙間が飛ばないよう、余白も拡大量と一緒に増やす。resetSystemIconState・detach・画面消灯・設定OFF・モジュール解除で解除し、15秒の単回上限を設ける。毎フレームのキャプチャ、Compose状態/引数/slotの書き換え、恒常ポーリングはしない。

Android17限定の既存allowlist内で完全な型/メソッド/フィールド契約が揃う場合だけ導入する。Android16のフックは変更しない。設定は調整タブの「充電演出中もステータスバーを表示」。初期値ON、全体スイッチに従う。変更は次回の充電演出から適用する。

純正APK・逆コンパイル結果・端末ログは公開ソースへ含めない。geometryの回帰試験8件で通常位置、拡大、spring反転、alpha、余白の連続性、他の移動との重複、異常値を確認する。実機検証結果は後続の検証追記へ分ける。

## 2026-10-31 検証

- JVM回帰試験136件（追加13件）とrelease lintが成功。release配布スクリプトでライセンス58件、API 102、検証用Activity不在、alignment、継続署名を検査した。
- 実機の抜き差し録画で、祖先のクリッピングと、準備時に非表示の通信速度表示の取り漏れを検出した。クリッピングを充電・プライバシー移動で参照カウント共有し、速度の実TextViewを登録する方式に修正した。
- One UI 9では非表示の従来BatteryMeterViewが幅0のまま残る場合がある。実描画を観測した専用Composeビューをアンカーとして使用する。純正のBatteryMeterViewのalpha操作は変更しない。移動量は小数座標の変換行列で計算し、丸め誤差によるフィードバックを避ける。
- 最終コードは同じ実機で充電イベントの一時シミュレーションを行い、録画で時計・通知の表示維持、通信速度と右側アイコンの同時移動、縮小後の位置復帰を確認した。診断値はcompleted=1、speedViews=1。シミュレーションはfinallyで解除し、実際のUSB充電状態に戻した。
- クリッピングの独立プロセス試験3項目（祖先全体の解除、併用中の保持、最後の解放と多重close）も成功。最初の試験fixtureはAndroid 17のApplicationSharedMemory初期化不足で終了したが、fixture内だけで初期化して再試験した。SystemUIのクラッシュではない。
- 設定ファイルは試験前後で一致。OSのboot IDとsystem_server PIDも一致。SystemUIのみ専用Reloadアプリ経由で読み込み直した。音声再生、OS再起動、ソフトリブートは行っていない。

確認はSM-S948Q / BZI9の縦画面・LTRで実施。Android 16実機、RTL、全画面アプリやロック中の充電、同時イベントの全組み合わせは再試験していない。Android 16は新フック導入対象外、RTL・別displayは純正経路へ戻す。

別件として、既存PrivacyDotsにはScreenDecorationsとmain間のスレッド違反を記録した。充電経路の例外ではなく、今回その処理は変更していない。全モジュールのログが無エラーであるとは扱わない。

左右の移動の補間に対し5件の試験を追加した。段階的な左移動・右への復帰・途中の方向反転の速度保持・60/120Hzの等価性・長い停止時間と異常入力の抑制を確認する。終了時の純正translationX=0をafter hookで検出し、描画前に現在位置を復元するため、最後のフレームで瞬間移動しない。

補間追加後も同じ実機で充電イベントを再現し、録画の連続フレームで左移動と終了後の段階的な右移動、速度表示の同時移動と復帰を確認した。充電イベントのシミュレーションは解除済み。

## 0.6.22: 通常の電池への受け渡し

0.6.21で保持していた純正alpha経路を調査すると、終了時は進捗0.95未満でBatteryMeterViewを透明に固定し、専用Composeビューへは値を配信していなかった。実機ではExiting開始から約90msでChargingVIの別effectがクリア処理へ入り、300msの縮小・フェードをcancelすることも確認した。

新しい処理では、登録済みの実描画Composeビューを優先して選び、通常の電池のglyph寸法をgetAnimatorOutへ渡す。専用Composeのalphaと、既存Viewのalphaを条件付きで所有し、終盤だけ切り替わるゲートを滑らかな補間へ置き換える。充電ラベルは測定済みpercent矩形の中心に向けて移動する。通常の電池も充電ラベルも実Viewのまま描画し、ビットマップやCompose引数・slotの変更は行わない。解除時には所有していた値だけを復元する。

片付けのeffectは元のshouldHide=false、label=0、同じchipで、getAnimatorOutから450ms以内の場合だけ、Samsung APK内のDelayKt.delayに元のContinuationを渡してsuspendする。期限後は同じContinuationで元のinvokeSuspend本体を実行する。label、completion、Compose Stateは変更しない。失敗・キャンセルのResult.Failureは遅延させず元の処理へ通し、画面消灯・OFF・対象のdetach後に新しい待ちは作らない。

JVM 140件とrelease lintが成功。実機APKと同じcoroutine runtimeを独立プロセスへ読み込んだfixtureでは、通常のsuspend/resumeが1回で完了すること、JobキャンセルでResult.Failureが返ることを確認した。同じfixtureで配布APKのViewalpha補間・多重close・外部変更を上書きしない復元も確認した。初回fixtureではR8後に存在しないJobKt.Job factoryを呼んで終了したため、実在するJobImplのconstructorへ直して4項目を再実施した。これは独立fixtureの失敗で、SystemUIのクラッシュではない。

実機の詳細・録画・設定は非公開のtooling/charging-handoff-20261031/privateへ保存する。満充電では充電演出を開始しないため、検証時だけdumpsys batteryのUSB・status・levelを一時シミュレーションし、finallyでresetして実値へ戻す。鍵・ログ・逆コンパイル結果・fixtureは配布APKへ含めない。既存PrivacyDotsの別件のスレッド違反はこの変更の検証と分ける。

最終版の実機録画では通常のCompose電池を選択し、文字位置を47フレームで更新した。純正ログ上、Exiting開始から片付けまで約450msが確保され、縮小・フェードが中断されずに通常表示へ戻った。最後に実充電状態への復帰、設定ファイルとOS boot ID・system_serverの一致、インストールAPKとrelease APKのハッシュ一致を確認した。確認はSM-S948Q / Android 17 BZI9で、Android 16実機と全同時イベントの再試験は含まない。
