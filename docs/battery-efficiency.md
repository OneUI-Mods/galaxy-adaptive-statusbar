# 待機中の電池消費を減らす（0.7.6）

画面が消灯・ロック中の5秒タイマーと、モジュールOFF／エラー停止中の500msタイマーをなくしました。停止時には従来どおり描画を復元し、キャプチャとミラーを解放します。画面ON・ユーザー解除・設定変更の通知と、既存のステータスバーレイアウトイベントで解除状態への復帰を検出し、1回の処理を起こし、必要な場合だけ通常の周期へ戻ります。

設定は初回取得とContentObserverの変更通知で取得します。成功後の約750msごとの再取得をやめ、起動時・一時失敗時だけ再試行します。失敗した取得も時刻を記録し、即時の再試行ループを避けています。消灯中に再試行タイマーを残しません。内部のmotion_endpoint登録通知は設定変更と区別します。

新しい背景の要求がキャプチャ中に届いた場合は、16msごとの待機確認をやめ、ワーカー完了から次の処理へ進みます。連続イベントは1件に集約します。キャプチャ予算・通常の更新周期・フェード・文字ごと／パーツごとの判定は維持します。

診断にConfiguration readsを追加しました。これは設定の実取得回数で、画面の解析回数ではありません。停止状態に移った際の診断は1回更新します。

JVMの仮想時計で通常周期、5時間の消灯、OFF・エラー停止、初回設定待ち、解除復帰、処理中の連続要求、close後の再予約拒否を確認します。これらは周期とイベントの検証であり、端末全体の電池持ちやmAhの測定ではありません。

検証結果: 209件のJVMテスト、releaseビルド、release lintを通過しました。実際の消灯時間に比例した電池消費の比較は未測定です。
